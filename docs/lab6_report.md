# Лабораторная работа №6

**по дисциплине «Конструирование программного обеспечения»**  
**Тема: Прототипирование**

## 1. Выбор задач и цель создания прототипа

Тема курсового проекта — «Разработка web-приложения анализа цен на товары». Приложение предназначено для хранения информации о товарах и ценах в разных магазинах, просмотра истории изменения стоимости и сравнения предложений.

Для прототипирования выбраны четыре взаимосвязанные функции из списка задач, сформированного в лабораторной работе №1:

1. просмотр и добавление товаров в каталог;
2. ручное добавление записи о цене с указанием магазина и даты;
3. сравнительный анализ последних цен по магазинам с вычислением минимальной, максимальной и средней цены;
4. визуализация динамики изменения цены на графике.

**Цель прототипа** — проверить понятность пользовательского сценария и реализуемость основных функций выбранного проекта до разработки полноценной серверной части. Прототип также позволяет уточнить требования к каталогу и истории цен, определить недостающие проверки и скорректировать план работ.

## 2. Реализация прототипа

Прототип реализован как клиентское web-приложение на React с использованием Vite, HTML и CSS. Это соответствует клиентской части технологического стека, выбранного в лабораторной работе №4. Сервер на Spring Boot и база данных PostgreSQL в текущем прототипе не подключены.

Реализованы следующие возможности:

- **Обзор:** основные показатели, график динамики цены выбранного товара и список последних цен по магазинам.
- **Каталог товаров:** просмотр списка, поиск по названию и категории, добавление новой позиции.
- **Добавление цены:** выбор товара, указание магазина, цены и даты замера; проверка обязательных полей и положительного значения цены.
- **Предотвращение дублирования:** прототип не принимает две записи для одного товара, одного магазина и одной даты.
- **Сравнение:** вывод последних цен по магазинам для выбранного товара, сортировка по цене и расчёт минимального, максимального и среднего значения.
- **История:** отображение записей о ценах на линейном SVG-графике с отдельной линией для каждого магазина.
- **Сохранение в браузере:** товары и записи о ценах сохраняются в `localStorage`, поэтому они остаются доступными после перезагрузки страницы в том же браузере.

При первом запуске отображаются демонстрационные товары и цены. Пользователь может добавлять собственные позиции и записи. Для вычислений вынесены отдельные функции в `frontend/src/lib/priceUtils.js`; для них добавлены модульные тесты в `frontend/src/lib/priceUtils.test.js`.

### Ограничения прототипа

Прототип не является законченной системой. Авторизация пользователей, полноценное редактирование и удаление товаров, импорт CSV/XLSX, подключение внешних источников цен, работа через REST API, серверная проверка прав, хранение в PostgreSQL, экспорт отчётов в PDF/Excel и развёртывание на сервере не реализованы. Данные хранятся только в браузере и не синхронизируются между устройствами.

## 3. Проверка прототипа

Для проверки основных сценариев предусмотрены следующие действия:

| № | Проверяемый сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Открыть раздел «Каталог товаров» | Отображается список демонстрационных товаров |
| 2 | Найти товар по названию | Список фильтруется по поисковому запросу |
| 3 | Добавить новый товар | Новый товар появляется в каталоге и доступен в списке выбора |
| 4 | Добавить цену с положительным значением | Запись добавляется, показатели и график обновляются |
| 5 | Попытаться добавить цену 0 или отрицательное значение | Форма не принимает некорректную цену |
| 6 | Повторить запись для того же товара, магазина и даты | Появляется предупреждение о дублировании |
| 7 | Открыть «Сравнение цен» | Цены упорядочены по возрастанию, рассчитаны минимум, максимум и среднее |
| 8 | Перезагрузить страницу | Добавленные данные сохраняются в локальном хранилище браузера |

Модульные тесты для `priceUtils.js` проверяют фильтрацию записей выбранного товара, сортировку истории по дате, расчёт статистики, обработку пустого списка и выбор последней цены по каждому магазину. Для запуска прототипа следует установить зависимости frontend и выполнить команды, приведённые в инструкции в корневом `README.md`.

## 4. Уточнение требований и влияние на план проекта

Прототип показывает, что базовый пользовательский сценарий можно построить в выбранном frontend-стеке без подключения сложных библиотек визуализации: для демонстрационного графика достаточно SVG. При этом реализация на клиенте не снимает необходимости создать серверные API, схему базы данных и тесты интеграции.

По итогам прототипирования целесообразно уточнить следующие вопросы с преподавателем:

1. Должен ли товар определяться только названием или дополнительно нужны производитель, штрихкод и единица измерения?
2. Может ли для одного товара и магазина существовать несколько записей за один день, например из-за разных акций или фасовок?
3. Какие периоды должны быть доступны при сравнении цен: неделя, месяц, произвольный интервал?
4. Нужно ли загружать цены из файлов CSV/XLSX в первой версии или достаточно ручного ввода?
5. Какие форматы отчётов обязательны для первой версии — CSV, Excel или PDF?

План проекта следует сохранить по крупным функциональным направлениям, но перед полной реализацией нужно добавить отдельные подзадачи на REST API, хранение данных в PostgreSQL, валидацию на сервере, обработку ошибок, интеграционные тесты и подключение frontend к backend. Ранее сделанные оценки из лабораторной работы №2 остаются предварительными: прототип подтверждает реализуемость основных клиентских сценариев, но пока не проверяет трудоёмкость импорта файлов, авторизации и серверной интеграции.

### Предварительный план следующих работ

| Направление | Что уже проверено прототипом | Что остаётся реализовать |
|---|---|---|
| Каталог | Просмотр, поиск, добавление товара | Полный CRUD, серверная валидация, сохранение в PostgreSQL |
| История цен | Ручное добавление и локальное хранение | REST API, связи между товарами, магазинами и ценами, миграции БД |
| Сравнение | Минимум, максимум, среднее, сортировка по цене | Фильтры периода, дополнительные правила расчёта и обработка больших объёмов данных |
| Визуализация | График по демонстрационным данным | Подключение к API, фильтрация дат и проверка пустых/неполных наборов данных |
| Импорт и отчёты | Не входят в текущий прототип | CSV/XLSX, экспорт PDF/Excel, обработка ошибок |
| Пользователи | Не входят в текущий прототип | Регистрация, аутентификация, права доступа |

## 5. Вывод

В ходе лабораторной работы был подготовлен прототип web-приложения анализа цен на товары. Для прототипа выбраны каталог товаров, ручной ввод цены, сравнение предложений и визуализация истории изменения стоимости.

Прототип позволяет оценить основной пользовательский сценарий до реализации полной системы и выявить требования, которые нужно уточнить: правила идентификации товара, дублирование цен, выбор временных периодов и состав отчётов. Отдельно подтверждена необходимость серверного хранения и интеграции frontend с backend, поскольку текущий вариант использует только локальное хранилище браузера.

План работ необходимо дополнить задачами на REST API, PostgreSQL, интеграционные проверки и загрузку данных из файлов. Таким образом, прототип не заменяет полноценную реализацию, но снижает неопределённость по основным пользовательским функциям и помогает более обоснованно планировать дальнейшую разработку.
